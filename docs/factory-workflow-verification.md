# Проверка защищённого приложения через workflow

Если доступ к приложению уже хранится в GitHub Actions, фабрика может получать
результат проверки из того же workflow выпуска. Локальная копия пароля не нужна.
В настройках проекта включается проверка через workflow; `artifactName` по умолчанию
в интерфейсе равен `factory-verification`. Адреса здоровья, версии и сценария,
а также ожидаемый текст остаются частью согласованного снимка плана.

Workflow обязан проверить приложение после выпуска и загрузить один artifact с
выбранным именем. В ZIP должен лежать `factory-verification.json`:

```json
{
  "schemaVersion": 1,
  "sha": "0123456789012345678901234567890123456789",
  "workflowRunId": 12345,
  "checkedAt": "2026-11-14T18:00:00Z",
  "readOnly": true,
  "platform": { "sha": "0123456789012345678901234567890123456789" },
  "health": { "url": "https://app.example/healthz", "status": 200 },
  "version": {
    "url": "https://app.example/version",
    "sha": "0123456789012345678901234567890123456789"
  },
  "scenario": {
    "url": "https://app.example/",
    "expectedText": "Data updated",
    "passed": true
  }
}
```

Поля заполняются по наблюдаемому результату. `platform.sha` — фактическая версия
на платформе, например имя каталога, на который указывает текущий релиз.
`version.sha` читается из запущенного приложения. Проверка сценария должна
подтвердить согласованный пользовательский результат. Создание JSON без этих
проверок не является допустимым доказательством.

Фабрика принимает квитанцию только от найденного успешного workflow текущей
попытки, проверяет ID запуска, оба SHA, адреса, текст сценария, время и read-only
режим. Архив ограничен размером, проверяется по SHA-256 из GitHub и читается без
распаковки в рабочую копию. Credential GitHub не передаётся на адрес временного
хранилища. Секреты приложения, cookies и заголовки авторизации в artifact запрещены.

В этом режиме отдельный GitHub Deployments record не обязателен: версия платформы
подтверждается квитанцией реального выпуска. Это позволяет использовать существующую
доставку без добавления workflow прав `deployments: write`. Обычная HTTP-проверка
по-прежнему требует совпадающий record платформы и все проверки приложения.

Возврат использует тот же договор проверки для предыдущего подтверждённого релиза.
Один зелёный статус workflow или один HTTP 200 не создаёт подтверждённый результат.
Старые квитанции без проверки версии и сценария остаются историей, но не считаются
доказательством проверенного выпуска.
