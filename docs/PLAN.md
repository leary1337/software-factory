# План фабрики

Личная фабрика на форке [Warren](https://github.com/jayminwest/warren) 0.19.3 (MIT, автор Warren проект больше не поддерживает). Работает на Mac владельца и на его подписке Claude Code. Владелец запускает и останавливает её вручную, агент работает один за раз. Цель: вести несколько проектов, старых и новых.

Это личный форк, а не проект Warren и не сервис warren.run.

## Как проходит задача

1. В интерактивной сессии идея превращается в спецификацию и тикеты: `grill-with-docs`, `to-spec`, `to-tickets`. Тикеты лежат в Seeds внутри репозитория проекта.
2. Владелец запускает план в Warren. Цепочка стартует только по его команде.
3. Запуск реализации работает в песочнице, проходит `qualityGate` и открывает PR на GitHub.
4. Отдельный запуск ревью читает diff без контекста реализации.
5. Если есть замечания, запуск доработки правит ту же ветку. После двух неудачных доработок задача возвращается к владельцу.
6. Владелец читает PR и сливает его сам. Только после этого стартует следующий тикет, время ожидания не ограничено.

## Роли

Если скилл есть в обоих наборах, берём один источник. Скиллы pstack в запусках читаются по пути, потому что инструмент Skill их не вызывает. Запуск никогда не ждёт человека, поэтому скиллы-допросы работают только в интерактивной сессии.

| Где | Роль | Модель | Скиллы |
|---|---|---|---|
| Сессия владельца | Постановка | на выбор владельца | Пококк: `grill-with-docs`, `domain-modeling`, `to-spec`, `to-tickets`, `wayfinder`, `prototype` |
| Запуск | Реализация | Sonnet 5.5 | pstack: `poteto-mode`, `architect`, `typescript-best-practices`; Пококк: `tdd`, `diagnosing-bugs`, `codebase-design`; свой скилл для Go |
| Запуск | Ревью | Opus 5.5 | Пококк: `code-review`; pstack: `interrogate`, `blast-radius`; проверка безопасности в промпте роли |
| Запуск | Доработка | Sonnet 5.5 | На основе `pr-fixer`; Пококк: `diagnosing-bugs`; правит только то, что назвал ревьюер |

## Что дописываем в форк

- **Доставка скиллов.** Адаптер Claude Code не доставляет скиллы, а `HOME` запуска отделён от `~/.claude`. Копии с записанными версиями источников лежат в репозитории фабрики и перед запуском кладутся в `HOME` запуска, а не в рабочую копию. pstack подключается целиком из сборки `harness/pstack/claude-code`, потому что его скиллы ссылаются друг на друга. Из набора Пококка берём только выбранные скиллы. Ставим один раз и не обновляем.
- **Роли ревьюера и доработки** и шаг ревью в цепочке PlanRun между открытием PR и ожиданием слияния.
- **Команда подключения проекта** с двумя сценариями. Старый проект: настройка скиллов Пококка, `create-verification-skill`, `GLOSSARY.md`, Seeds, `.warren/config.yaml` и `qualityGate`, всё одним PR. Новая идея: `grill-with-docs`, новый репозиторий из шаблона, те же настройки.
- **Шаблон новых проектов.** Go 1.25 для бэкенда, React, TypeScript, Vite, Tailwind и shadcn/ui для интерфейса. Python только для ML и данных, Next.js только если нужны SSR или SEO. Старые проекты остаются на своём стеке.
- **Свой скилл для Go** и проверки `golangci-lint`, `go test -race`.

## Настройки

| Настройка | Значение |
|---|---|
| Harness | `claude-code`, вход по подписке |
| Runtime | `local` (`sandbox-exec` на macOS) |
| Сеть в песочнице | `restricted`, выход только по списку доменов |
| Трекер | Seeds |
| Git-хостинг | GitHub, токен только на подключённые репозитории |
| Проверки | Локальный `qualityGate`, GitHub Actions не используем |
| Автослияние | выключено, каждый PR читает владелец |
| `WARREN_AUTOMATIC_MAX_CONCURRENT_RUNS` | `1` |
| `WARREN_PLAN_RUN_MERGE_TIMEOUT_MS` | `0` |
| `maxCostUsd` на запуск | `10` (оценка по ценам API, страховка от зацикливания) |

Память проектов ведёт Mulch (`mulch: on`). Раз в неделю владелец запускает `retro` и `correct`. Уроки закрепляются проверками и линтерами, изменения самой фабрики идут только через PR. Автоматических патрулей нет.

Репозиторий публичный: в нём нет настроек приватных проектов и логов запусков.

## Этапы

Всё проверяется на одноразовом тестовом репозитории, пилотный проект выбирается позже.

1. Форк и очистка.
2. Локальный запуск на подписке и с ограниченной сетью.
3. Доставка скиллов и проверка, что агент их видит.
4. Роли ревьюера и доработки, полная цепочка.
5. Команда подключения и шаблон проекта.
6. Удаление лишнего: Kubernetes, GCP, Jira, Azure DevOps.

## Что проверить на этапах

| Вопрос | Этап |
|---|---|
| Условия подписки для автоматического запуска: прямого запрета не найдено, явного разрешения тоже. Читает владелец | 2 |

## Что выяснилось на этапе 6

- Удалены Kubernetes, GCP, Jira и Azure DevOps. Общий код запуска внутри контейнера, нужный Docker, перенесён в `src/runtime/container`.
- Исторические записи в `docs/design`, `ROADMAP.md` и `ACCEPTANCE.md` оставлены как есть и ещё упоминают удалённое.

## Что выяснилось на этапе 5

- Проект подключает команда `/connect-project` в сессии из корня фабрики, механику выполняет `scripts/connect-project.ts`.
- Шаблон лежит в `factory/template`, его проверка качества `scripts/check.sh` проходит и в песочнице агента.
- GitHub-токен Warren ограничен выбранными репозиториями, поэтому каждый новый проект надо добавить в него вручную.

## Что выяснилось на этапе 4

- Цепочка работает: PlanRun запускает `implementer`, затем `reviewer`, при замечаниях `rework` в ту же ветку и повторное ревью. Итог публикуется комментарием в PR, следующий тикет ждёт слияния.
- Для Opus 5.5 нужен Claude Code не старше 2.1.280. На Mac стоит 2.1.319.
- Встроенный `security-review` в режиме `-p` недоступен, поэтому проверка безопасности описана прямо в промпте ревьюера.
- Запуск без коммитов Warren завершает как `no_changes`. Для шага ревью это нормальное завершение.
- Тикет закрывается после слияния из отдельного клона: в `git worktree` команда `sd` пишет в основную копию.

## Что выяснилось на этапе 3

- Скиллы лежат в `factory/skill-pack`, версии источников записаны в `LOCK.json`. Перед каждым запуском они копируются в его `HOME`.
- Сборка pstack работает через `--plugin-dir` в режиме `-p`: агент видит 58 скиллов pstack и оба его субагента.
- Скиллы Пококка вызываются инструментом Skill. Скиллы pstack он отказывается вызывать, поэтому в промптах ролей они указываются путём `$HOME/.claude/factory/pstack/skills/<имя>/SKILL.md`.

## Что выяснилось на этапе 2

- Запуск на подписке и список доменов работают: агент открыл PR, `github.com` доступен, `example.com` заблокирован.
- **Останавливать Warren можно только между запусками.** Ctrl-C во время работы агента завершает запуск как `sandbox_run_lost`, его коммиты не отправляются на GitHub и PR не открывается.
- **Агенту нельзя уводить команды в фон.** Claude Code заканчивает ход раньше, чем завершается фоновая команда, а Warren считает запуск успешным. На этапе 4 в промптах ролей нужен запрет на `run_in_background`.
