# Локальная фабрика

Фабрика работает на этом Mac. Codex запускается обычным процессом от текущего
пользователя: системной песочницы и Docker-runtime нет. Для каждой задачи создаются
отдельная Git-копия и домашний каталог; отмена и таймаут завершают дерево процессов.
Эта схема рассчитана на доверенные проекты. Linux/VPS остаётся будущим этапом.

## Установка из репозитория

Нужны Bun, Git, Node/npm, uv и локальный Chrome. Codex CLI должен быть авторизован
через ChatGPT. GitHub CLI используется для существующего доступа к репозиториям.
Go нужен только проектам с рецептом Go. Системы управления задачами и памятью
не требуют отдельной настройки владельцем.

```bash
bun install --frozen-lockfile
bun run ui:install
bun run build:ui
bun run factory:start
```

Откройте адрес, который напечатал запуск. Рабочий интерфейс содержит задачи,
проекты и настройки. Закрытие вкладки не останавливает службу и очередь.
При повторном открытии интерфейс загружает сохранённое состояние сервера.

В настройках проекта отдельно выбираются исполнитель и ревьюер, модель каждой
роли, подготовка окружения и доставка приложения. Сохранённые настройки имеют
версию. Для готовности проекта нужны конкретная команда проверки, схема выпуска,
проверка версии и здоровья приложения, пользовательский сценарий и возврат.
Несовместимый стек или недостающие сведения отображаются как причина остановки.

## Согласованный план

Перед стартом сохраняются полный текст задач, критерии, зависимости, разрешения,
границы выпуска, бюджеты, профили агентов и версия общего набора инструментов.
Один старт запускает этот снимок. Изменение оставшейся части плана создаёт явную
ревизию; уже начатые задачи сохраняют прежние параметры.

Каждая задача проходит реализацию, независимое ревью и проверку зафиксированного
коммита в отдельной чистой копии. Выпуск происходит после всего плана или явно
отмеченного этапа. Слияние PR ещё не означает проверенный выпуск приложения.
Карточка показывает наблюдаемые доказательства, причину остановки и следующее
действие. Неизвестный исход внешнего действия сначала сверяется; слепого повтора нет.

## Общие навыки и MCP

Источники находятся в `factory/skill-pack/` и `factory/toolkit/catalog.json`.
Фабрика сохраняет неизменяемые версии набора в своём каталоге данных. В настройках
можно проверить текущий кандидат, применить его или выбрать предыдущую версию.
Активные планы продолжают использовать зафиксированный набор.

Для первоначального подключения личных CLI из этого репозитория:

```bash
bun scripts/factory-toolkit.ts install --home "$HOME"
bun scripts/factory-skills.ts --home "$HOME" --format agents
bun scripts/factory-skills.ts --home "$HOME" --format claude
bun scripts/factory-toolkit.ts enroll --home "$HOME"
```

Первые три команды показывают изменения. Последняя подключает оба личных CLI к
общему набору и последующим обновлениям из интерфейса. Чужие настройки и
отредактированные вручную файлы не перезаписываются. Набор не содержит credentials.
Claude Code получает совместимые файлы; выполнение фабрики остаётся на Codex.

Exa и Context7 работают анонимно с бесплатными лимитами. Graphify извлекает только
локальный код с отключёнными модельными backend. Playwright запускает локальный
Chrome с отдельным профилем. Платные услуги и автоматическая покупка квот исключены.
Недоступность дополнительного инструмента допускает достаточное альтернативное
доказательство; отсутствие обязательной проверки останавливает задачу.

## Состояние и обслуживание

Каталог данных, база SQLite, рабочие копии и история принадлежат одному серверу.
Перед обновлением сохраняется проверенная копия. Восстановленная очередь не
запускается параллельно с оригиналом. Исторические запуски удалённых runtime
остаются доступны для чтения.

Проверки разработчика описаны в [AGENTS.md](../AGENTS.md). Для изменений запускайте
целевые тесты, затем один общий `bun run check:all --bail` на итоговых файлах.
Для UI дополнительно нужен `bun run check:ui-visual --build`.
